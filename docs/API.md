# Collector data model (idea#414)

The HTTP contract the UI calls is Pixel's `idea-usage-api/1` (`web/API.md` on `pixel/dashboard-ui-415`). This file is the collector-side model: how export records land in SQLite and how they are shaped for those endpoints.

Day-file schema: `idea-usage-day/1` (Axle, [agent-engine-dev#308](https://github.com/koenswings/agent-engine-dev/pull/308)). Export stream: NDJSON envelopes `{type: presence|day|sample, payload}` ending with `{type: end, counts, errors}`. Exit 10, empty stdout and stderr `disabled` means monitoring is off; that is stored as a kit state, not as a pull error.

## SQLite (`./data/usage.sqlite`, WAL)

| Table | Purpose |
|---|---|
| `kits` | engine, tailscale_name, school, deployment_id, optional IANA timezone, monitoring_enabled, last_pulled, note |
| `uplink_samples` | timestamp, engine, online, last_seen, via (`direct` \| `DERP` \| null), latency_ms |
| `uplink_transitions` | timestamp, engine, from_state, to_state (`online` \| `offline`) |
| `presence_samples` | raw pulled `idea-usage-presence/1` objects |
| `presence_segments` | `state` (`on` \| `off` \| `gapUnknown` \| `collectorGap`), start, end, length_known |
| `presence_days` | on_minutes, school_hours_on_minutes, boots, longest_gap_minutes, length_known |
| `daily_summaries` | engine, deployment_id, day, **instance**, app, name, demo, listed, hook_status, skip_reason, payload (full stored day file), pulled_at |
| `samples` | pulled `idea-usage-sample/1` rows (Nextcloud Office snapshots, including opaque `documentIds`) |
| `help_events` | id, deployment_id, offered_on, tutorial_chapters, note, created_by, created_at |
| `pull_log` | success, error, rejected, or **disabled** |
| `collector_gaps` | idea-side sidecar outages |
| `meta` | includes U-7 threshold settings: `thresholds` (JSON of the seven keys), `thresholds_updated_at`, `thresholds_updated_by` |

The kit files do not carry a deployment id. idea maps `(engine, day)` to `deployment_id` when a pull is stored (registry: `./data/registry.json`).

## Aggregation rules

- The day-file identity field is `instance`. HTTP responses also send `instanceId` as an alias of the same value.
- Census and Nextcloud `setup` come from the last `hookStatus: ok` day in the week and are not summed. Nextcloud `setup` and `logins` use singular `admin` / `teacher` / `learner` keys, each `{total, beyondSeed}`. `beyondSeed` is read from the hook; it is `null` when the hook omitted it. The collector does not invent it (no `teachers - 1` heuristic). `otherGroups` stays on Nextcloud `setup`. Kolibri HTTP `setup` is Pixel's flat `Census` (the hook's RoleCount totals are mapped into `learnersRegistered` / `teachers` / `admins`).
- Activity counters (sessions, minutes, page views, workflow events, office opens/read/edit) are summed across ok days. On a Nextcloud *instance*, weekly `office.distinctDocuments` is the last ok day's value (not a sum or max of days). Scorecard `officeDistinctDocuments` is the **sum across the school's own Nextcloud instances** (document ids are salted per instance, so two own Nextclouds hold different documents and the sum is correct). Kiwix `distinctArticles` is the max of daily counts (the export does not include the article set, so a true weekly union is not available).
- `clockTrusted` (school-week and per-app week responses) is `false` only if a contributing `hookStatus: ok` day-file for that week had `clock.synced === false`. `no-hook`, `unlisted-no-hook` and `skipped` stub rows do not contribute, and neither do `timeout` / `failed` / `invalid` rows. Each row is attributed only to its own `day` (a later snapshot is not copied onto earlier days or weeks). If an instance has no ok day that week, its `clock` is `null`. A week with no contributing ok-rows has `clockTrusted: true` (the field is a boolean, not null). A null/missing clock on an ok-row does not taint the week.
- Stub / failed day files keep `hookStatus` (`ok` \| `timeout` \| `failed` \| `invalid` \| `skipped` \| `unlisted-no-hook` \| `no-hook`) and optional `skipReason`. App payloads on those days are treated as null; they do not overwrite an earlier ok summary.
- Nextcloud `office.byGroup` stays numeric (`{admin, teacher, learner}`), not RoleCount. `appsOpened` is an object (`{ "files": n }`). `workflows` uses `fileDropLinks` and `fileDropUploads`.
- The scorecard Nextcloud block matches Pixel's `ScorecardNextcloudInputs` (`worksheetShares`, `editShares`, `fileDropLinks`, `fileDropUploads`, `schoolFilesShares`, `officeOpens`, `officeDistinctDocuments`, `officeRead`, `officeEdit`, `officeEstimatedMinutes`) plus two collector-side splits from `office.byGroup`: `officeOpensTeacherLearner` (teacher + learner) and `officeOpensAdmin`. Total `officeOpens` is unchanged. If a week's own Nextcloud instances have no `byGroup` (old day files) while `opens` is greater than 0, both split fields are `null` rather than `0` — we do not invent a role split. When some instances have `byGroup` and others do not, the splits sum only the known groups (so `officeOpens` may be larger than teacher+learner+admin). `officeDistinctDocuments` is the sum across the school's own Nextcloud instances (see above). Setup extras are `nextcloudTeacherBeyondSeed` and `nextcloudLearnerBeyondSeed` (null when the hook did not emit `beyondSeed`). Workflows (`worksheetShares`, `editShares`, `fileDropLinks`, `fileDropUploads`, `schoolFilesShares`) have no `byGroup` in the Engine day file; they stay unsplit totals.
- Presence segments for a school week cover Monday 00:00 through Saturday 00:00 (the end of `weekEnd`, Friday) in kit-local time — the same window Pixel's strip draws. They are contiguous, non-overlapping, and sum to that window. Unmeasured stretches are filled explicitly: `off` where the export shows the kit was off; `collectorGap` only where a watchdog `collector_gaps` interval (sidecar down) covers the hole *while monitoring was known to be on*; `gapUnknown` otherwise. A kit that has never had monitoring enabled has a week of all `gapUnknown`, with no `collectorGap`. Periods covered by `disabled` polls, and any time before monitoring was first successfully pulled, also stay `gapUnknown` rather than `collectorGap`. `lengthKnown` is true for measured `on`/`off` and for collector gaps that have both a start and an end; it is false for `gapUnknown` and for an open-ended collector outage.
- `presence.summary` is a short plain sentence such as `On 4 of 5 school days, 31 h in school hours`, built from `presence_days` school-hour totals. It is `null` when those roll-ups are missing. It is never an empty string.
- Uplink samples and transitions use the same offset-aware week bounds as presence (Monday 00:00 to Saturday 00:00 in the kit's registry timezone). Timestamps are compared as parsed instants, not as naive `T00:00:00` strings, so `Z` and `+02:00` values near a Monday/Saturday boundary fall on the correct side. `GET .../uplink` also sends `measured: boolean`: `true` when at least one idea-side Tailscale sample was stored for that week, `false` when `samples` and `transitions` are empty. Uplink is not in the kit `idea-usage-export` stream (that stream is `presence`, `day`, and `sample` only). The collector records it by polling the sidecar Tailscale LocalAPI (`/localapi/v0/status`) via `record_uplink`. An empty week with `measured: false` means no sidecar samples were stored (for example the sidecar has not joined the tailnet), not that a presence `on` window was filtered out.
- `GET /api/v1/weeks`.`currentWeekStart` is the latest Monday with stored data (daily summaries or presence days). `GET /api/v1/meta` adds `todayWeekStart` (today's Monday) and `currentWeekHasData` (true when at least one stored week exists). The weeks list also repeats `todayWeekStart` and `currentWeekHasData` next to `currentWeekStart`. If the store is empty, `currentWeekStart` falls back to `todayWeekStart` and `currentWeekHasData` is false.
- `port` on the instance breakdown is always null: it is not in the export.
- `KitTimezone.utcOffset` is the kit's offset at Monday 00:00 of the requested week, derived from the registry IANA `timeZone` via zoneinfo, for every kit, whether or not it has stored samples. If the registry has no IANA name, `utcOffset` falls back to the latest presence sample's RFC 3339 offset, then to `+00:00`. `timeZone` is the optional IANA name from the registry; without it the label is `kit local time (UTC±n)`. If a school week spans a DST change, both endpoints are still local midnights in that zone (so the window length may be 5 days ± 1 hour). The single `utcOffset` field is the offset at week start; segment timestamps carry their own RFC 3339 offsets. EU and US DST changes fall on Sunday, outside this Mon–Sat window, so those kits see a constant offset through the school week.
- Each overview `SchoolCard` is one kit (`engine` + `deploymentId`). It includes `monitoringEnabled` with the same meaning as on `KitListItem` and `SchoolWeekResponse` (that kit's current flag). A school with several kits has one card per kit; the field is not an any-of aggregation and there is no separate monitored-kit count.
- `helpSuggestions` on the overview is server-owned and uses the shared U-7 thresholds (`helpAfterAmberWeeks`, default 3). The collector offers help when monitoring is on and either there is no pulled usage data yet, or the kit has been below the scorecard thresholds for that many consecutive school weeks. Grey weeks (no data) never count toward the streak and do not break it; a green week resets it. Each overview `SchoolCard` also has `unused: boolean`, set when a help event was recorded and the kit stayed amber with no improvement for `unusedAfterHelpWeeks` (default 4) school weeks after that event. Unused schools are not added to `helpSuggestions` (that banner always says “offer help”; unused means help was already offered). The UI (`web/src/pages/FleetOverview.tsx`) prefixes a non-empty list with “Offer help first.” and renders each `message` verbatim. Scorecard HTTP responses still send raw inputs, not colours; tones are computed server-side only to drive these streaks.
- The HTTP API is same-origin (no CORS headers). The UI is served from the same host.

## Endpoints (served by this collector)

See Pixel's `web/API.md`. Additions that are not in that draft:

| Method | Path | Notes |
|---|---|---|
| `GET` | `/api/v1/health` | Unauthenticated and cheap (no database). `{"ok": true, "schema": "idea-usage-api/1", "version": "<x-app.version>", "commit": "<sha or null>"}` so the Engine healthCheck can probe `${port}`. `version` is the App `x-app.version` (currently `"1.0"`). `commit` is the dashboard git SHA: `USAGE_DASHBOARD_COMMIT`, or `/etc/idea-usage/build-info.json` baked at image build, or the Engine bundle directory `usage-dashboard-<sha>` parsed from `/proc/self/mountinfo`. `commit` is `null` when none of those are available. |
| `GET` | `/api/v1/settings/thresholds` | Operator session. `{thresholds, defaults, updatedAt, updatedBy}`. `thresholds` are the effective values (defaults until an operator saves a change). `updatedAt` / `updatedBy` are `null` until then. `updatedBy` is the operator username, matching `help_events.created_by`. |
| `PUT` | `/api/v1/settings/thresholds` | Operator session. Body is a partial `{thresholds: {...}}` or `{reset: true}`. Returns the same shape as GET. Invalid input answers `400` with `{error, field}` (a flat pair, not the usual `{error: {code, message}}` envelope — see Pixel's contract). |
| `PUT` | `/api/v1/session/password` | Operator session. `{currentPassword, newPassword}` (new password at least 8 characters). Updates the hash for the signed-in operator in `./data/operators.json`. Wrong current password: `401`. Short new password: `400`. |

`GET /api/v1/session` without a cookie returns `{authenticated: false}` so the login page can ask. `POST /api/v1/session` (login) and `DELETE /api/v1/session` (logout) are also reachable without a cookie — otherwise nobody could sign in. Every other `/api/v1` path, including `PUT /api/v1/session/password`, requires the `idea_usage_session` cookie.

Operator accounts are exactly `koen` and `marco` (U-9). There is no `admin` account. First-run seed passwords come from compose (`IDEA_USAGE_KOEN_PASSWORD`, `IDEA_USAGE_MARCO_PASSWORD`) and are stored as salted PBKDF2 hashes in `./data/operators.json`. A later password change is not reset on restart. See `docs/accounts.md`.

`GET /api/v1/meta` also returns `todayWeekStart` (Monday of today), `currentWeekHasData`, `thresholds` (the effective U-7 values), and `thresholdsConfigured: true` now that Koen approved the defaults. `GET /api/v1/weeks` returns `currentWeekStart` as the latest Monday that has stored data, plus `todayWeekStart` and `currentWeekHasData`.

Threshold keys and defaults: `availableMinSchoolDays` 3 (integer 0–5), `teachingCycleMinItems` 1 (integer ≥ 0), `learnerSessionShareMin` 0.5 (number 0–1, learners as a share of Kolibri *sessions*, not minutes), `nextcloudMinActions` 1 (integer ≥ 0; worksheet shares + edit shares + school-files shares + file-drop uploads + `officeOpensTeacherLearner` — Office opens by a teacher or learner. Admin opens do not count. A null split, from old day files with no `byGroup`, contributes 0), `wikipediaMinViews` 10 (integer ≥ 0), `helpAfterAmberWeeks` 3 (integer ≥ 1), `unusedAfterHelpWeeks` 4 (integer ≥ 1). Set up is a yes/no line with no number (yes when registered learners and teachers are both > 0, or, with no Kolibri census, when a Nextcloud beyond-seed count is > 0).

Consistent snapshots use `VACUUM INTO` under `./data/backup/`, keeping 14 copies.
